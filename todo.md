## Релиз 2 (пока не решено)

- **Обмен результатами между пользователями.** Обезличенный подписанный
  пакет результатов из локальной базы: провайдер (ASN), тип блокировки,
  цель, стратегия, профиль клиента, успехи и попытки. Перед выгрузкой
  видно всё, что уйдёт. Импорт проходит Validator и служит априорным
  знанием для бандита, чужие данные весят меньше своих.
  - Шаг 1: файл `.ztpack`, которым делятся в чате или на форуме.
  - Шаг 2: децентрализованный канал (общий репозиторий с PR пакетов,
    Nostr-релеи или p2p), подписка по желанию, отзывы «работает у меня»,
    PoW против спама.
  - Телеметрии нет: ничего не уходит без явного действия пользователя.
- **Чат с ассистентом внутри AutoTuner.** Пока только ТЗ:
  https://claude.ai/code/artifact/2abb1580-9313-4090-9802-dc2b72d87ba8
- **Релей в один клик и пробитие NAT** для доступа к AutoTuner или
  zapret-gui извне. Только опционально, выключено по умолчанию.
- **Удалённый VPN-доступ к роутеру через NAT в zapret-gui.** Проектируется
  отдельно, в AutoTuner не делается.
- **Бандит с рукой «LLM»** и замер связки «бандит + модель» на живых
  данных.

## Хвосты релиза 1

### Подбор на роутере (zapret-gui)
- Пачки по 2–5 кандидатов в одном эксперименте во время перебора:
  `RouterTrialExecutor.RunBatchAsync` готов, но `StrategySearch` пробует
  кандидатов по одному.
- Проверка победителя с ПК через роутер (L2/L3) во время `keep_best`
  перед окном подтверждения.
- Авто-доподбор по обратной связи с роутера: сейчас повтор испытаний
  запускает пользователь.
- Блобы из файлов и свои Lua-скрипты в экспериментах на роутере.

### Самообучение и замер (M6)
- Сценарий `d-cutoff-white` на стенде: бандит берёт 41 испытание против 1
  у обычного порядка (исправить без отказа от данных своего провайдера
  пока не удалось).
- Замер модели и связки «бандит + модель» с настоящим ключом или локальной
  моделью: `dotnet run --project src/ZapretAutoTuner.Bench -- --provider …`.
- На стенде нет сценария с наказанием (нет соединения после неудачи).

### MCP, советник, мост
- Лимиты советника (12 ходов, 30 вызовов, 400k токенов) не настраиваются
  в интерфейсе; нет потокового вывода; ходы советника не попадают в
  «Собрать отчёт» (кроме аудита вызовов).
- Отчёт о неудаче не передаётся советнику целиком, модель собирает те же
  данные инструментами.
- Лог движка (`--debug`) не входит в наблюдение испытания для MCP.
- Если окно открыто с выключенным HTTP и запускается `ZapretAutoTuner mcp`,
  открывается вторая копия программы со своим Agent.
- MCP-испытания и эксперименты не могут вызывать даже одобренные свои
  Lua-функции: `StrategyPolicy` пускает только функции каталога.
- Ответы `resource_get` и `resource_diff` маскируют адреса, поэтому
  записи ipset через MCP читаются замаскированными.
- Мост: нет транспорта WebSocket; нет уведомления клиенту об изменении
  списка инструментов роутера (обновится при следующем `tools/list`);
  ручная проверка с настоящим расширением, роутером и claude.ai не
  проводилась. В README MCP-SuperAssistant claude.ai пока нет в списке
  поддерживаемых сайтов.

### Безопасность и сборка
- Windows: winws2 читает хостлисты и ipset'ы с правами администратора,
  junction в папке данных может указать на защищённый файл (содержимое
  не уходит в сеть, но лучше отдавать их Agent как содержимое, как блобы).
- `--debug=@`, `--hostlist-auto` и `--hostlist-auto-debug`: проверка
  симлинков перед запуском сужает окно гонки, но не закрывает его;
  надёжно — Agent сам создаёт эти файлы в своей папке.
- Переносные архивы (zip, tar.gz): `bundle.json` лежит в той же
  незащищённой папке, поэтому для работы с правами администратора
  рекомендуются установщик, .deb или .rpm.
- Версия Inno Setup в `choco install` не закреплена (обычно он уже есть
  на сборочной машине GitHub).
- Предупреждение в интерфейсе, если программа запущена от администратора.
